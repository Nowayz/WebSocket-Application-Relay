# Reject reserved departed-session IDs — 2026-10-19

Native routing reserves ID zero for relay commands and u64::MAX for broadcast/disconnect envelopes; neither identifies a session. The bridge previously accepted either as the departed ID inside an upstream disconnect event and forwarded a bogus legacy notification. The selected change checks that decoded ID before constructing the legacy event. It uses the existing unsupported-reply Close path for invalid upstream data, without adding state, queues, locks, dependencies or configuration.

Valid IDs remain unsigned 64-bit values through u64::MAX-1. Their legacy representation is unchanged: eight 0xff bytes followed by the departed ID's eight little-endian bytes. The native [routing/ID contract](../../protocol.md#routing) remains unchanged, including the earlier native fix that reports the actual departed ID after takeover. This check does not maintain a second membership registry or establish that an arbitrary non-reserved ID actually departed; membership truth remains the upstream relay's responsibility.

The focused regression fails on the previous implementation. It verifies nine valid IDs across encoding widths through u64::MAX-1, both reserved IDs, and five mistyped payloads that remain rejected. All 126 library tests pass in 0.49 seconds, warnings-denied bins/lib/test-target Clippy passes, and all 65 JavaScript protocol/legacy/idle checks pass in about 1.12 seconds, with all six checked resource gauges retired.

A controlled upstream sends an event followed by a valid variable result. Four cases (departed IDs zero, u64::MAX, one and u64::MAX-1) run against each frozen release binary. The control forwards all four notifications; the selected build forwards only the two valid ones and preserves their order before the following variable result. Reserved-ID cases complete the existing frontend Close 1003 / `Value Requires CBOR Client` path. No Close code is newly introduced. Accepted cases complete normal frontend/backend Close/EOF; rejected cases retire the backend by EOF or reset. Every one of the eight case processes exits zero without a forced kill, its controller thread finishes, and descriptors return from 10 to 10.

This is an event-schema and ordering fixture with a synthetic upstream. It does not test real backend membership emission or establish throughput, latency, mass-user capacity or long-duration stability. Existing JavaScript integration coverage still checks real legacy disconnect notification delivery. No large-population campaign was needed for this bounded ID check.

The control is the previous selected acknowledgement-validation release; the selected build is a fresh clean snapshot with exact source hashes and `fresh:false` in its manifest. Source snapshots are compressed alongside their patch, manifests, logs, complete commands and raw wire receipts. Existing running services, convenience binaries and unrelated source edits were preserved. There is no performance-gain claim.

From a clean checkout, run `cargo test --locked --lib disconnect_events_preserve_valid_ids_and_reject_reserved_departures`. From the repository root, `probe.py --server PATH --output FRESH.json` reproduces the four wire cases for either binary using Linux descriptor checks and owned disposable loopback processes. The probe records observed frames; `python docs/benchmarks/2026-10-19-bridge-departures/verify.py` audits saved source/binary identities, rejection boundaries, exact legacy bytes, ordering and cleanup offline.
