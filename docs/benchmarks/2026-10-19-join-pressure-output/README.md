# Preserve short prejoin-test evidence — 2026-10-19

The prejoin-pressure tool could truncate an existing server log and then fail to save a receipt if the OS refused to execute the server. A controlled run of the original implementation confirms both outcomes. The selected tool checks the receipt and derived server-log paths, including dangling symlinks, before any child starts. It reserves a new receipt with exclusive creation and opens its log exclusively. Existing artifacts remain intact.

Server hashing and Popen now run inside the guarded cleanup/receipt scope. Missing files, missing execute permission and missing shebang interpreters produce failed JSON receipts. A null `server_exit_code` means no server handle was created; the exception is retained and the CLI exits 1. Existing launched-server termination, bounded kill/reap fallback, real-wire checks and final success criteria are preserved. This is artifact/error-path reliability work, with no relay runtime or performance claim.

The two fast test methods exercise seven subcases: receipt/log collisions with regular files or dangling symlinks (four), and three real Unix startup failures. All seven failed against the original source; all pass after the change in 0.003 seconds. Separate subprocess CLI probes confirm exit 1, a readable failed receipt and empty newly created logs for all three startup failures. No server process was created in those cases.

One fresh real-socket check uses 32 pending upgraded connections, one wave and a two-second absolute join deadline. It passes all Close/EOF, policy, exact counter, routing and final resource checks while the independent joined witness verifies 226,696 messages. The disposable server exits zero without a forced kill. This finite correctness fixture is not a latency, throughput or 100,000-user capacity benchmark. Its server hash and full command are retained in `real.json.gz`; existing manual services and unrelated worktree edits were preserved.

The path preflight is intended for sequential runs, as are the existing benchmark tools. Exclusive receipt/log creation prevents replacing a conflicting path at those creation points; it is not an atomic transaction across both artifacts or a cross-process benchmark lock. Select a fresh output basename. If a conflicting log appears after preflight, log creation can fail before the guarded server scope and leave the reserved receipt empty, with no child started. This change does not claim to cover every failure during filesystem setup.
