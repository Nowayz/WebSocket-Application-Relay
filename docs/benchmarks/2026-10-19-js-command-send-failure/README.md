# JavaScript command-send failure isolation, 2026-10-19

Source base `7b5ca68`. Selected fix: when a command send throws, reject that request with its original thrown value and close an otherwise-open WebSocket with code 4002 / Relay Command Send Failed. The existing ready-state checks then reject queued controls before another frame is sent. A socket already closing/closed is not closed again or given a replacement reason. Ordinary application send(), encoding failures before dispatch, valid command serialization, timeouts and final-close cleanup keep their existing behavior. Reconnect before retrying a command after this send exception.

The wire protocol has no request IDs. A custom WebSocketClass or send wrapper can forward a command and then throw. Previously the client rejected that command but advanced its queue. A same-opcode late response could then resolve the next request. This is a fault-injected adapter failure; the evidence does not claim that the ordinary native WebSocket implementation spontaneously throws after accepting a frame.
