# Clean Close for upstream welcome failures — 2026-10-19

An upstream connection refusal already produced a bounded legacy Close 1013 / Upstream Unavailable. After a successful HTTP upgrade, however, an upstream TCP drop before its CBOR welcome or expiration of the welcome deadline propagated an error directly out of bridge(). The legacy client observed ResetWithoutClosingHandshake (typically browser code 1006), losing the useful retryable failure reason.

The selected bridge maps errors from the subscription/welcome phase to the existing bounded 1013 / Upstream Unavailable Close before returning the original error for logging and retiring its connection slot. The subscription write moves inside the same existing ten-second welcome deadline. An upstream protocol Close, mapped framing error, valid welcome or invalid welcome keeps its existing path. The error-handling change adds no protocol message, retry queue, runtime dependency or forwarding payload copy.

The welcome phase and the closing handshake have separate existing ten-second bounds. A responsive frontend acknowledges immediately; an unresponsive frontend can consume the closing budget after the welcome deadline. This is a per-phase policy, not a ten-second end-to-end setup deadline. The added tests share a fourteen-second outer watchdog because their TCP/HTTP setup is immediate and their frontends acknowledge Close; that watchdog does not replace production deadlines.

Both focused real-socket reproducers fail against the previous runtime: one peer drops TCP after receiving the native subscription, and one completes HTTP upgrade, receives the subscription, then waits without sending a welcome. Both legacy clients see ResetWithoutClosingHandshake. The failed-before run has two failures and takes 10.00 seconds. The stalled peer has no timer or test-side Close to cause the failure; bridge retirement ends its read.

After the fix, each case receives exactly Close 1013 / Upstream Unavailable before any legacy ID, acknowledges it, and completes the close. A subsequent connection on the same bridge receives valid legacy ID 42 and closes cleanly. The bridge has only one admission slot, so this verifies retirement and recovery without a restart. The observed post-join waits for Close are about 13.9 ms for EOF and 10.015 seconds for the deliberate stall; these are fixture observations, not latency guarantees. All 130 library tests pass in 10.05 seconds. Clippy with lib/tests and warnings denied passes. The real JS client integration suite passes all 65 checks in 1.126 seconds of test execution and returns all six checked resource gauges to zero. Builds/install/cleanup add wall time.
