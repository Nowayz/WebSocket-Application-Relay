# Reject inverted latency clocks — 2026-10-18

Selected tooling fix: the per-user comparison loader rejects an intended-send statistic or maximum below the corresponding actual-send value for the same user. These CSVs measure the same deliveries with two origins: intended-send includes nonnegative waiting before actual send. Their selected percentile, same-bin histogram bound and observed maximum must preserve that order.

Previously each clock's numbers were checked separately, so internally inconsistent rows could still produce valid-looking charts and threshold percentages. Four controlled rows demonstrate the gap: inverted exact percentiles, inverted exact maxima, inverted histogram bounds and inverted histogram maxima all pass the old loader. The selected check runs after both clocks have been read for a row and before the caller receives loaded data. It applies to the selected p99/maximum statistic and the exact maxima included in the summary. It does not claim to validate unused CSV columns, timestamp origins, packet completeness or the provenance of a benchmark run.

The old regression run has four failed subcases. All nine focused tests pass after the fix in 35 ms. Valid histogram bounds remain permitted to exceed their own observed maxima; their order between clocks must still be consistent. A separate nanosecond maximum fixture verifies the fanout format. The actual CLI rejects that inverted fixture with exit code 2 and creates no PNG, PDF or JSON output.

No new relay traffic was run. Eight retained private/fanout CSVs from the selected SIMD comparison and rejected window-timeout experiment were loaded in both p99 and maximum modes. All 16 cases have identical values, sample counts, maxima and numerical summaries before and after this change. These inputs cover four 100,000-user populations and their corresponding 8,192-reader fanout populations. Existing valid chart calculations are unchanged.

`build.json` pins the source base and selected scripts. The original and selected plotters, full regression logs, invalid CSV, CLI failure receipt, valid-data compatibility receipt and source patch are retained.
