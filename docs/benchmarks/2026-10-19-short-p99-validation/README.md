# Validate short-run per-user p99 consistency — 2026-10-19

The comparison loader previously accepted mathematically impossible short-run percentile rows. The capacity client's nearest-rank rule is ceil(99*n/100), as implemented in examples/capacity.rs for exact samples and histogram ranks. For every positive n below 100, that rank selects the largest observation. Thus an exact p99 must equal its observed maximum; a histogram p99 upper bound must cover that maximum. At n=100 the rank is 99, so p99 can legitimately be lower. This is a rank identity, not an arbitrary minimum sample policy or a statistical confidence threshold.

The selected loader validates that identity in both actual-start and intended-start clocks when reading p99 values. Exact millisecond and nanosecond CSVs reject unequal values with fewer than 100 samples. Short histogram rows reject bounds below their maximum, while preserving valid bounds above it. Maximum-only analysis continues to ignore unused p99 columns. Existing finite/nonnegative and cross-clock ordering guards remain. No relay runtime, sample collection, workload, protocol, dependency or numerical calculation changes.

Reports now include p99_sample_scope, with the number of users whose sample counts make nearest-rank p99 select their maximum and a finite-observation explanation. The count does not claim that larger-sample percentiles differ from their maximum: repeated/tied durations can still make them equal. It also does not establish statistical reliability or a long-term percentile guarantee.

The failed-before run has 11 test methods and 18 failing boundary subcases. The selected suite has 12 methods and passes in 0.328 seconds. Coverage includes counts 1, 8, 99 and 100; both clocks; exact milliseconds/nanoseconds; histogram bounds; and maximum mode independent of unused p99 fields. A separate CLI regression rejects impossible short-run data with exit 2 before saving PNG/PDF/JSON artifacts. The earlier nearest-rank aggregation test used internally inconsistent ten-sample examples with p99 below maximum; its sample counts are corrected to 100 while preserving the same latency expectations.

Ten retained real CSVs (five 100,000-user private populations and their five 8,192-reader fanout populations) are loaded in p99 and maximum modes. All 20 comparisons preserve values, sample counts, maxima, thresholds and numerical summaries. Only the new explanatory metadata is added. equivalence.json records paths and results. A real CLI run on the latest 100,000-user CSV succeeds and reports all 100,000 users under the rank-maximum condition; its JSON is retained as current.json. No new relay traffic was needed.
