# Authenticate configured token bytes without ASCII coercion

Selected: the shared HTTP management authorization helper borrows HeaderValue::as_bytes(), strips the existing exact b"Bearer " prefix, and passes the remaining bytes to the unchanged constant-time secret_matches helper. This replaces the to_str ASCII-only conversion and subsequent string-to-byte conversion. It adds no credential allocation, Unicode normalization, decoding, policy branch or dependency. Every protected HTTP handler continues using the same helper; the no-token metrics policy is unchanged.

Config already accepts UTF-8 admin tokens. The locked http 1.5.0 HeaderValue can retain non-ASCII field bytes, while to_str validates visible ASCII. Consequently a correctly supplied UTF-8 token containing π/世界 was always unauthorized. Comparing its existing bytes makes the configured secret usable when the HTTP transport supplies those exact bytes. This report tests direct raw HTTP/1; it does not claim that every HTTP client or intermediary can encode/preserve non-ASCII Authorization values. The prefix remains exact and token equality remains byte-for-byte.

Two regressions fail against the original helper: a direct HeaderMap comparison and a real HTTP management request. The byte test covers ASCII/Unicode success, altered tokens, wrong scheme, malformed UTF-8 credentials and missing credentials for metrics and management authorization. The real loopback test preserves 401 for missing/altered credentials and requires 200 for the exact UTF-8 token on the paginated channel endpoint. It uses a two-second failure guard and checks the empty relay census and graceful server retirement.

The selected clean snapshot passes all 116 library tests in 0.53 seconds, both secret-encoding CLI integration methods in 0.02 seconds and strict bins/library/test Clippy. It also passes all 65 JavaScript/native/original relay.js/legacy/idle cases in 1.122 seconds, with no skips and all six checked resource gauges zero. Build/install/setup add wall time. The existing uncommitted relay/C++ prototypes are excluded from these builds.

An independent release controller starts four disposable native processes: original/selected crossed with ASCII/UTF-8 fixture tokens. It checks 11 requests per process, 44 total excluding readiness polling. Missing, altered, malformed and wrong-scheme credentials remain 401. ASCII correct credentials retain channel/metrics 200, drain/resume 204 and readiness 503/200 transitions. Original Unicode correct credentials remain 401; selected Unicode credentials now have the same successful channel/metrics/drain/resume transitions as ASCII. Every process exits zero and no token appears in its captured logs. No existing service or user data is touched.

This is a management correctness fix. It removes the ASCII scan but establishes no throughput, latency, 100,000-user or constant-time timing measurement. Packet routing, admission, FIFO, shared body ownership and native connection layout are unchanged. Runtime source outside the common authorization chain is byte-identical before the cfg(test) section.

Original/selected source, exact patch, failure/pass logs, release controller/receipt, provenance and frozen build manifest are retained. Run python verify.py for the saved-evidence check, or cargo test --lib admin::tests in the intended source snapshot for the focused Rust cases. The archived release controller uses repository-local frozen executables and a fresh output guard; choose new output paths before repeating it. All credentials in the evidence are synthetic fixtures.
