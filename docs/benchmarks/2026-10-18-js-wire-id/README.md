# JavaScript wire-ID validation — 2026-10-18

Selected: validate received IDs as exact uint64 integer values, with nonreserved values required for sessions. The old welcome check excluded only 0 and BROADCAST, accepting negative/out-of-range integers. Incoming senders and disconnect IDs also used BigInt coercion directly. This could accept strings/booleans as identities, dispatch malformed IDs, or update the client's identity from a malformed assignment acknowledgement.

A shared wireId helper accepts only number/bigint inputs, rejects unsafe Number integers and uint64 range violations, and optionally excludes reserved session IDs. Welcome/construction, sender, departure and assignment acknowledgement paths use it. Control sender 0 and disconnect-notification sender BROADCAST remain valid. Malformed established responses dispatch an error and close with 1002; invalid assignment acknowledgements reject the pending request without changing userId. The outgoing target API retains its existing conversion policy. Valid IDs above 2^53 remain exact BigInt values.

Five in-memory tests cover reserved/negative/oversized/fractional/unsafe/coercible identities, valid high IDs, departure events and assignment completion. Original tests reproduce the negative/invalid-ID acceptance; before/after output is retained. Unit checks finish in roughly 62 ms. The real native/bridge suite now includes these unit tests and all seven existing integration tests: all 12 pass in 1.09 seconds, including BigInt routing/takeover, object/byte/text values, concurrent variable commands, legacy interoperation and idle handling. Disposable services exit normally with zero final live connection/session/queue/variable gauges. Manual services are untouched. Browser bundling succeeds; this check does not claim a new browser UI interaction test.

A separate synchronous receive-path component screen dispatches a prepared MessageEvent through the real client decoder and EventTarget handlers. Each fresh process warms 20,000 messages and measures seven batches of 100,000 messages; every sender/payload and the final 720,000 count are verified. Event reuse, JIT/code layout and one tiny fixed payload limit inference; no allocation count or concurrent workload was measured.
