# Build current sources before the JavaScript fixture — 2026-10-19

The supported JS runner could execute a different copied source snapshot's cached binaries when both snapshots shared a Cargo target directory and the current inputs had older timestamps. Merely reading executable paths from Cargo's artifact messages did not establish source freshness. This reproduced with the current toolchain in two minimal local Cargo projects: one changed both root and vendored code, and one changed only vendored code. The old runner finished Cargo in 0.00 seconds and executed `A-A` instead of `B-B`, or `same-A` instead of `same-B`.

The selected runner refreshes modification times for in-tree src/vendor files and the root Cargo manifest/lockfile before building. It uses touch's no-create mode, preserving input contents and leaving missing files missing, and builds with `--locked`. Registry sources are not touched. It then accepts only the requested binaries reported for the current canonical manifest, with Cargo explicitly reporting `fresh:false` for each. Custom `CARGO_TARGET_DIR` paths continue to come from Cargo's executable fields. Incorrect or unconfirmed artifacts stop the script before fixture launch.

This deliberately rebuilds local crates on each check, even when their bytes have not changed. The input tree must be writable for timestamp refresh; normal source snapshots/checkouts satisfy that requirement. It trades a small build cost for faithful fixture execution. It is not an atomic input snapshot or a substitute for keeping builds sequential and source files stable while Cargo runs. Source bytes, relay runtime behavior, client protocol and fixture policy are unchanged.

The fast regression has four subcases across two methods. Two use real Cargo builds sharing a temporary cache, including an actual local path dependency. Their intentionally failing executables write compiled root/dependency identities and never open listeners; stub npm/curl commands avoid installation and network probes. Two controlled artifact streams claim either a cached binary or a foreign manifest and prove that no executable starts. All four fail against the original runner; all pass after the fix in 0.729 seconds. The fixture directories and processes are owned and cleaned by the test.

A separate real check runs the updated script from a fresh archived source tree with the existing custom shared debug target, without manually refreshing its Rust files. Cargo recompiles both patched transport crates and the relay in 2.71 seconds. All 65 JavaScript protocol/legacy/idle checks pass in about 1.12 seconds, and the six checked connection/session/queue/variable/read/output-capacity gauges retire to zero. Build/install and fixture cleanup add wall time. This is source/build reliability evidence, not a runtime performance gain or a mass-user acceptance claim.

Run `python scripts/test-js-build-freshness.py` for the four fast subcases and `bash -n scripts/check-js.sh` for shell syntax. Use the normal `CARGO_TARGET_DIR=PATH ./scripts/check-js.sh` from the intended source tree for integration. The test generator, original/selected script, patch, compiler identities and before/after/integration logs are retained here; `python docs/benchmarks/2026-10-19-js-build-freshness/verify.py` audits saved evidence offline. Existing manual services and pre-existing source edits were preserved.
