# Consistent authorization for malformed disconnect IDs — 2026-10-18

Selected: matched `POST /v1/sessions/{id}/disconnect` requests return `401` for missing or incorrect management credentials, including malformed IDs. Authorized malformed IDs keep the existing Axum `400` status and diagnostic body. Authorized valid IDs without a live session keep `404`, and a successful authorized disconnect remains `204` with WebSocket Close `4000`.

Previously Axum's `Path<u64>` extractor rejected malformed IDs before the handler ran, so those unauthorized requests returned `400`. Valid session disconnects already required credentials. The change accepts `Result<Path<u64>, PathRejection>` and checks authorization before returning a captured rejection. Axum still performs extraction; this defers the rejection response, not the extraction work. It reuses Axum's existing parser and error response without introducing manual numeric parsing or changing route matching. Unmatched routes and public health endpoints retain their behavior. No packet-path or performance change is claimed.

One real HTTP regression test fails against the old handler immediately. It then passes after the change, covering text, negative, overflowing uint64 and invalid-UTF-8 IDs, the reserved endpoints of the uint64 range, a valid absent ID and public liveness. All 90 working-tree library tests pass in 0.55 seconds, strict all-target Clippy and formatting pass, and a clean release snapshot builds. The three user overlays were excluded from the release snapshot and preserved in the working tree.

Independent disposable release probes exercise old and selected binaries. Each makes 20 non-disconnecting management requests with missing, wrong or valid credentials, interleaving 20 checked private CBOR deliveries to show the sessions remain usable. Old malformed requests return `400` for every credential case; selected missing/wrong cases return `401`, while authorized responses have exactly the same status and body as control. Both probes then authorize a live-session disconnect, receive and acknowledge `4000`, validate the surviving peer's ordinary departure notification, complete its normal Close, and return resource gauges to zero with clean process exit. Routing payload copied bytes and protocol errors remain zero.

The initial disposable fixture had an import-name collision before issuing requests. The second version completed all management and private-delivery checks but expected a Close acknowledgement before consuming the room's normal departure message. Those failed fixture sources, logs and partial receipts are retained. The final probe validates the departure in order and passes for both binaries; no server behavior was changed to accommodate these fixture corrections.

`build.json` pins the source base, exact selected admin source and both frozen binaries. `raw/selected.patch.gz`, full test/build logs, all fixture versions, raw-client dependencies and HTTP response receipts are retained. Run `python docs/benchmarks/2026-10-18-admin-path-auth/verify.py` to verify checksums and compare response bodies offline. It starts no server.

No native/bridge convenience binary or running service was replaced. Existing FIFO, queue admission, shared body ownership and the three pre-existing dirty source files are unchanged.
