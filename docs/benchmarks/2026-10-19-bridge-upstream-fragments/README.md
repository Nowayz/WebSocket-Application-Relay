# Bound upstream fragment parsing with the existing poll quota

Selected production change: enable the existing 256-frame-per-stream-poll limit on the upstream WebSocket immediately after connecting, before sending the subscription or reading the welcome. The legacy frontend already sets this limit; the upstream leg previously retained the adapter's unlimited default. The fix is one line and introduces no policy setting, queue, allocation, copy or new scheduler.

A completed application message can contain arbitrarily many empty continuation frames while using very few application bytes. With no frame quota, the decoder can consume the whole train in one poll without yielding. The vendored adapter's existing limited path preserves incomplete input/fragment state, self-wakes and returns Pending after the quota when no complete message is available. This gives other runtime tasks an opportunity to execute, including during the bounded welcome wait. It does not preempt processing inside one large frame or impose a wall-clock deadline on a poll.

The focused current-thread real-TCP regression writes a 513-frame message: one empty non-final binary frame, 511 empty continuations, then one final continuation carrying the encoded welcome. The mock upstream completes the write before enabling poll counting. A wrapper counts polls of the actual bridge future. The client must receive exactly the original legacy ID after at least three polls. It then releases a second 513-frame train carrying one CBOR data envelope and verifies the full legacy sender/payload after at least three polls. Both sides finish a normal Close exchange.

Against the original runtime logic, the regression fails immediately at the welcome yield assertion. With the one-line fix, recorded bridge polls are exactly three for welcome and three for forwarding; the focused test completes in 0.04 seconds. This counter includes polls of the whole connection future and can also include socket readiness wakes, so it is not a CPU or timing benchmark. Prewriting the small train avoids deliberately delayed fragment arrivals as an explanation for its yields. The old failure and the adapter's bounded-poll implementation support the regression; no universal per-task scheduling-latency claim follows.
