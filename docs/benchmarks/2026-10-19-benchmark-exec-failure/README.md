# Preserve failed benchmark receipts when server exec fails

Selected: inspection.py and capacity.py launch the server inside their existing guarded error/cleanup block. They initialize child handles first and handle a missing server object during cleanup. An OS exec failure after exclusive receipt creation now records passed=false, the original OS error, empty server/client logs and a null server exit code. No load client is launched. Capacity cleanup also records actual server/client return codes on failed runs after those children retire. Existing CLI failure behavior remains: inspection returns a failed outcome, capacity re-raises after saving its receipt, and both CLIs exit nonzero.

Previously both runners opened their fresh receipt and then called Popen before entering try/finally. A readable but non-executable server file, or an executable script with a missing interpreter, raised before error recording. The reserved receipt remained empty. This was distinct from an executable that starts and exits during readiness, which already had coverage.

A new regression exercises both OS failures in both runners (four subcases) without launching a relay. A separate executable client would write a marker if started; that marker must remain absent. Against the original runners all four fail to parse the empty receipts. With the fix they parse the saved PermissionError or FileNotFoundError, passed=false, null server exit and empty logs. The missing interpreter is inside each temporary directory, keeping the fixture independent of global executable paths.

All eight receipt/preflight test methods pass in 0.756 seconds, including the four new subcases, collision/symlink preservation, profile guards, invalid packet sizes and the existing started-server readiness failure. The two mixed-output regression methods also pass. Four separately archived CLI receipts confirm both error classes and exit status 1; no client marker appears. The tests retain exclusive creation, so an earlier receipt is not overwritten.

Two separate one-second ordinary smokes use the frozen current native executable: inspection has two private pairs; capacity has 32 users in two-member rooms. Both verify their existing full payload/FIFO/counter/proof/Close/retirement gates and client/server exit zero. Six final resource gauges are zero. Small native arenas retain their existing warm-slot policy. These are launch/cleanup compatibility checks, not a throughput or latency comparison. Measured intervals still begin after successful server launch, as before. No packet handling, workload bounds, native source, frozen executables, service deployment or protected worktree overlay changes.

The original/selected scripts, patch, before/after logs, four failed receipts and two successful receipts are archived. Run python verify.py for the saved-evidence check, or python scripts/test-inspection-output.py to rerun the bounded regressions. It starts only temporary fixture executables; the four OS exec cases cannot run the server program or load client. Large-user or long-soak testing is unnecessary for this startup-only correction.
