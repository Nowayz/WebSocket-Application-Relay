# Preserve capacity-test latency and profile artifacts — 2026-10-19

A successful short capacity run could overwrite an existing per-user latency CSV and its derived window-summary JSON even when its receipt used a fresh name. The Rust example writes both files using File::create. The Python capacity runner previously reserved only its receipt; profile collisions were checked after children had started, and different newly requested outputs could resolve to the same destination.

The selected runner preflights its receipt, exact-latency CSV and derived `.windows.json`, histogram CSV, and the selected perf data/counter output before resource setup or child launch. Regular files and dangling symlinks are rejected. Resolved output identities must be distinct, preventing a new CSV or profile from colliding with the new receipt/timeline. It derives the window filename using Rust's extension behavior, including trailing-dot and hidden filenames. The check immediately before profiler startup also uses the actually selected profile mode and detects dangling symlinks. No timing path, relay code, protocol, workload limit or dependency changes.

The original tool was run with 16 users and one traffic second against disposable processes, with pre-existing CSV and timeline sentinels. The run passed every protocol/counter/resource check and exited zero, but replaced both sentinels. Its receipt and resulting files are retained as the counterfactual. This is demonstrated artifact loss, not a relay failure.

The initial 16 added preflight cases failed on the old implementation. The final two new test methods cover 18 cases: ten existing-file/dangling-symlink cases across exact CSV, timeline, histogram, perf data and perf counters; plus eight overlapping-path cases, including normalized `..`, trailing-dot and hidden-name aliases. The complete ten-method output/startup regression suite passes in 1.679 seconds. Marker executables prove rejection happens before the server starts; prior files/symlinks and fresh receipt paths remain unchanged.

Two independent valid-output smoke checks each run 16 users for one traffic second with four probes per user. Exact mode writes a CSV named `users.` and Rust's actual `users.windows.json`; histogram mode writes its bounded histogram CSV. Both pass, contain all 16 distinct users with four observations each, and exit server/client zero without forced termination. The native relay is the frozen expiry-fairness build; the capacity client is freshly built from a clean committed snapshot, with input hashes and fresh release artifact recorded. No full-population or long-duration rerun was needed for this filesystem preflight change. Existing services and unrelated source edits were preserved.

This is preflight protection for sequential fixtures, not an atomic transaction or cross-process lock across all outputs. The receipt retains exclusive creation. CSV/profile paths can still be raced after preflight; the raw Rust example's direct file-writing contract is unchanged. Use fresh basenames and the normal sequential benchmark discipline.

Run `python scripts/test-inspection-output.py` for the fast regressions. Source, patch, original sources, test logs, successful/counterfactual receipts, CSVs/timelines and client manifest are retained here. `python docs/benchmarks/2026-10-19-capacity-output-preflight/verify.py` checks their hashes, actual output loss in the counterfactual, valid output counts, identities, exact counter checks and retirement offline. No runtime speedup is claimed.
