# Reject incomplete profiler runs

Selected: a requested mixed-load profile must remain running through measurement until the controller stops it, then exit with an accepted controlled-stop status and leave a nonempty data file. The receipt records its exit code, profile byte count and SHA-256. Early exit is failure even when the profiler returns zero. Missing or empty data also fails. Clear errors identify the phase or missing artifact and preserve the perf log for diagnostics. Existing workload gates and finally-block child cleanup remain unchanged.

The original bug is reproduced with real disposable native/capacity/sidecar processes (32 private users and 16 fanout readers), while an injected `perf` executable returns zero either immediately or after 0.5 seconds. Both old-runner cases return zero with `passed: true` and no profile file. Logs retain the commands, reported success, missing-artifact result and target-reaping checks. This is false diagnostic success, not a relay payload failure.

The selected runner checks `poll()` after the existing 200 ms setup wait and before requesting shutdown. It rejects an already exited process in either place. It then records controlled-stop status, requires an existing nonempty file and hashes the file outside the timed phase. The CPU event, sample frequency, stack recording, target selection, traffic settings and phase timing boundaries are unchanged. A live process check cannot establish that perf has attached or sampled every instant. A nonempty file alone cannot establish meaningful sample coverage; inspect perf reports separately.

Four regression subcases pass in 7.963 seconds including setup and cleanup: immediate zero exit; zero exit during traffic; normal requested stop without data; normal requested stop with a zero-byte file. Each returns nonzero with `passed: false`, a specific error and recorded profiler exit code. All cases confirm the targeted client PID is gone; receipts record terminal statuses for all three child processes. The immediate-exit case also verifies no measured workload event was emitted. Missing/empty data cases retain a fake profiler until the controller sends SIGINT, testing the controlled-stop path rather than merely repeating startup failure. The tests use the same frozen-binary environment variables as test-mixed-load-gate.py.

A separate real-perf success fixture uses 32 users, 16 fanout readers and two seconds of traffic with two offered windows. It passes payload/FIFO/counter checks, 2/2 windows, clean application exits and complete resource retirement. Perf returns -SIGINT, an accepted controller-stop result. The receipt records 504,052 profile bytes and a matching SHA-256. The saved perf report parses successfully, contains 53 samples and zero reported lost samples. This proves the success path and metadata, not statistically meaningful performance. No relay or client implementation is modified.

The non-profile paced success, deliberately excessive offered load and unpaced integration cases also pass in 7.062 seconds total; the missed-load fixture still exits nonzero while correctness remains true. Six clock/descriptor tests and output-collision checks pass. All traffic phases are two seconds, and the immediate failure aborts before traffic. No multi-hour or full-population campaign is needed to demonstrate this bug. Test/profile execution is sequential.

The base is eb15f1c. Raw original/selected runners, selected patch, regression source, failing/passing logs, full live success receipt/CSV/timeline, real perf data/report, output-gate logs and helper source are archived. Run `python docs/benchmarks/2026-10-18-profile-integrity/verify.py` for an offline audit. Existing manual services and the three pre-existing source overlays remain untouched. This improves measurement integrity; it makes no claim of lower relay latency or CPU use.
