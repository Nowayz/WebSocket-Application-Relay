# Validate numeric user identity in fairness CSVs — 2026-10-19

The loader previously accepted any nonempty unique ID string. Consequently `1` and `01` represented two users in a fairness CDF despite naming the same numeric session, and malformed, reserved or out-of-range IDs could be counted as real users. Every supported relay exporter writes unsigned decimal uint64 session IDs; zero is the relay control ID and uint64::MAX is the broadcast sentinel, so neither can identify a connected user.

The selected loader requires ASCII decimal digits, parses exactly to a Python integer, rejects reserved/out-of-range values, and checks duplicate numeric identity. A single leading-zero representation is accepted; a second spelling of that numeric ID is rejected. Full-width integers retain exact precision and never pass through floating-point conversion. The original CSV remains untouched and its existing source hash is retained. This does not impose a new user-count or sample-count cap.

The failed-before 15-method suite has 42 failing subcases: 13 malformed/reserved/out-of-range forms plus a numeric-alias pair, across exact millisecond, exact nanosecond and histogram inputs. Forms include signs, separators, floating/scientific/hex notation, arbitrary text, whitespace, non-ASCII digits and uint64 overflow. The selected suite passes all 15 methods in 0.487 seconds. Boundary coverage accepts ID 1 via a single leading-zero spelling, ID 2 and uint64::MAX-1. Existing short-p99, clock, sample, threshold and artifact-preservation checks remain active.

Twenty-two retained real-data comparisons are numerically identical before and after: five 100,000-user private populations and five 8,192-reader fanout populations, each in p99 and maximum mode, plus the 16-user histogram CSV in bounded-p99 and exact-maximum modes. Values, sample counts, maxima, threshold results and complete summaries are unchanged. equivalence.json records source paths/hashes and modes. A real CLI request with IDs 1 and 01 returns status 2 with duplicate user ID before saving PNG/PDF/JSON artifacts; cli.json retains the command/result. No relay traffic or runtime change is involved.

Run `python scripts/test-user-latency-comparison.py` for focused checks or `python docs/benchmarks/2026-10-19-latency-user-identity/verify.py` to audit saved evidence. The selected/original source, patch and logs are retained. Existing manual services, convenience binaries and three unrelated dirty runtime files remain untouched. This is data-integrity validation for per-user analysis, not a runtime performance improvement.
