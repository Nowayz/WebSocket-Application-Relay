# Exact JavaScript response shapes — 2026-10-18

Selected: require decoded relay envelopes and control reply bodies to be arrays of exactly two elements. This adds two checks to the existing handler and uses its existing immediate rejection/error/Close policy. It adds no protocol mode, cache or payload copy.

Destructuring previously accepted arbitrary iterables. A CBOR byte string containing [1,2] could dispatch a sender-1 message with value 2; a control reply encoded as byte string [1,1] could resolve a listen command. Missing fields could resolve undefined and extra array fields were silently ignored. Both malformed acceptance paths reproduce before the fix. Nonarray values, byte-string lookalikes and arrays with missing/extra fields now close with protocol error 1002; malformed controls reject their pending commands.

Application values are still arbitrary CBOR values: valid envelope payloads include arrays of any length, objects, bytes, undefined, null and text. Shape checks apply to the wire envelope/control body, not to application arrays. BigInt identity handling and byte-buffer ownership are unchanged.

Nine focused in-memory tests pass in about 72 ms. The complete disposable native/legacy suite passes all 16 tests in 1.09 seconds, with normal process exits and zero final connection/session/queue/variable gauges. Browser bundling succeeds. No browser UI interaction or Rust runtime change is claimed.

The short component comparison uses the same real client decode/EventTarget path and prepared-message harness as the earlier wire-ID study: 20,000 warmup messages then seven batches of 100,000, verifying all 720,000 sender/value pairs. Four sequential fresh processes are pinned to CPU 4. Control medians are 236.04/218.14 ns; selected 227.40/226.12 ns. Ranges overlap, so no performance gain or clear regression is established. This is a synchronous one-payload component screen using event reuse, not socket throughput or concurrent user latency. Builds and other traffic did not overlap those batches.
