# Clean legacy Close after malformed upstream frames

Selected: report upstream WebSocket decoder failures to the healthy legacy peer using the existing bounded error-to-Close mapping, before or after the upstream welcome. Previously an error before welcome escaped through `?`, and an error after welcome matched the generic loop exit. Both dropped the legacy TCP connection without a Close handshake, exposing an unexplained 1006-style disconnect.

The fix reuses frame_error_close and transport::initiate_close. Protocol violations map to 1002 / Protocol Error, invalid text to 1007 / Invalid UTF-8, and capacity failures to 1009 / Message Too Large. The frontend can acknowledge and receive EOF. The faulty upstream decoder is not resumed; its socket is retired when the bridge task completes. Raw transport loss keeps the existing behavior. No new queue, timer, public setting, unsafe operation or ordinary payload allocation is introduced. The existing ten-second bounds and outer welcome deadline still apply.

One focused real-TCP library regression injects an invalid opcode, invalid UTF-8 text, a masked server frame and a 16 MiB-plus-one frame declaration. Each runs before and after a valid welcome, for eight cases through a bridge limited to one admitted connection. It checks exact Close code/reason, acknowledgement and EOF, with subsequent joins proving slot reuse. The oversized declaration needs only its ten-byte header, not a large body allocation.

The regression fails against original runtime logic both before welcome (0.00 seconds) and after welcome (0.04 seconds), receiving ResetWithoutClosingHandshake. To expose the second failure independently, the copied control test reverses its two stage loops; the final selected test covers both stages in the original order. All 112 clean-snapshot library tests then pass in 0.50 seconds, and strict library/test Clippy passes.

The freshly compiled frozen release bridge passes an independent standard-library Python/raw-WebSocket probe for all eight cases. A valid welcome and bad frame are deliberately coalesced into one upstream TCP write in post-welcome cases. Exact frontend Close/ACK/EOF and faulty upstream retirement are checked. One global admission slot is reused throughout. Bridge descriptors return from 10 to 10, and SIGTERM exits zero. The accepted eight-case phase completes in 0.007966 seconds; this is a functional check duration, not a relay latency benchmark or scalability measurement.

The first release-probe attempt ran no cases because inherited RUST_LOG=warn suppressed the startup line used for readiness. It exited the child cleanly. The corrected probe explicitly sets child-only RUST_LOG=info and TOKIO_WORKER_THREADS=4, with a fresh receipt. Both receipts are retained and labeled; only release-v2.json is accepted.

The supported JavaScript checker runs against clean-snapshot native/bridge sources with a custom target directory. All 61 native/CBOR/original relay.js/legacy/idle cases pass in 1.120 seconds, with no skips. All six checked final gauges (connections, sessions, queued bytes, variable bytes, read reservations and output capacity) are zero. Fixture children are cleaned up by the checker. Build/install/setup time is additional. Existing manual services, convenience executables and the three pre-existing dirty source overlays are unchanged.

The source archive, patch, failing/passing logs, release receipt/controller, frozen build manifest and provenance are beside this report. Run `python verify.py` for the archived-evidence check. To rerun the independent release probe from the repository root, use `python docs/benchmarks/2026-10-19-bridge-upstream-frame-errors/release-probe.py PATH_TO_BRIDGE FRESH_RECEIPT.json`; it imports the existing scripts/reference.py wire helper and starts only its own disposable bridge/upstream sockets. Build serially and use the frozen executable identity in build.json. No throughput benchmark or 100,000-user campaign is needed for this error-path correction.
