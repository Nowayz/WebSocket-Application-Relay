# Population heap attribution and native connection-slot gauge

2026-10-18, source base `5ed329c`. Selected change: one low-cardinality management gauge, `war_native_connection_slots`. It exposes allocated native slab capacity, occupied plus spare, aggregated across workers. It updates only when admission/retirement changes capacity and releases each worker's contribution on exit. A cached capacity costs one usize per worker; neither the per-connection layout nor payload storage grows. The ordinary packet-routing and socket output paths are unchanged. The gauge is a slot count, not bytes, RSS, an admission limit or a universal zero-after-disconnect invariant: small arenas intentionally remain warm.

Two sequential diagnostic runs first compare the same frozen selected Rust/C++ implementations and frozen clients used by the preceding ordinary comparison. Only the server allocator is replaced by gperftools libtcmalloc, with SHA and exact environment recorded. Two dumps per server are taken at the empty baseline and populated ready gates, before timed traffic resumes. The existing runner still checks all payload/FIFO/counter/census/retirement contracts. Each run uses two configured traffic seconds, 100,000 private users plus 8,192 readers, a publisher and a census connection; 32/32 fanout windows complete and all child processes exit zero. No independent churn, inspectors, extra pairs, TLS or remote network. Diagnostic CPU, RSS and latency are excluded from ordinary performance comparisons because the allocator and dumps change execution.

| Live allocation objects at ready | 343,717 | 445,614 |

These are requested heap bytes/objects, excluding allocator bookkeeping/free arenas, kernel socket memory and stacks; they are not normal-allocator RSS. Every parsed stack row sums exactly to the corresponding raw header. The baseline matters: C++ retains roughly 4 MiB in loop initialization even before clients. Fewer allocation objects does not imply a smaller retained heap.

Rust's major exclusive ready groups are 69,290,672 bytes at generic backing-vector growth, 21,638,800 at Worker::accept, 15,579,936 at generic exchange_malloc, and 9,489,360 at hash-table allocation. C++'s us_poll_resize group is 22,504,352 bytes. Thus the native socket allocation groups are similar in requested size; the large extra Rust backing storage is the more useful target than another guessed socket allocation optimization. Generic frames do not identify every caller: the report retains unresolved/generic categories and full symbol mappings rather than attributing all backing-vector bytes to one structure.

A clean release-mode layout probe measures Connection=520, Stage=320, Upgrade=288, WebSocket=320, Socket=184, SocketState=96, RateLimiter=48, Peer=80 and Budget=32 bytes. Socket plus the 16-byte Arc header matches the live 200-byte-per-connection group. Peer/Budget plus two Arc headers total 144 bytes per session, consistent with the generic allocation group's 216,388 objects and 15,579,936 bytes. The captured subscribe disassembly contains 48- and 96-byte allocations; generic stack attribution alone does not independently split that group. Layout is compiler/target/build specific, not a public ABI. The debug probe has larger Mio socket metadata, so the release result is used for these comparisons.

The selected binary's separate ordinary two-second population check reports 131,072 native slots for 108,194 sessions, then zero slots after exhaustive retirement. There are 22,878 spare slots at that ready gate. Multiplying 131,072 by the measured 520-byte connection record gives 65 MiB of record storage alone, consistent with the backing-vector group being dominated by connection metadata. This multiplication is not a claim of resident pages or complete allocator/slab overhead. The 320-byte decoder-bearing Stage is about 62% of Connection. Reducing that state would require preserving the general protocol parser, fragmented input, handshake resumption, deadlines and shared-owner lifetimes; no speculative decoder rewrite is selected here.

The one gauge makes the allocator-capacity distinction visible without profiling. Unit coverage checks aggregation across two workers, idempotent updates, retained warm capacity, release of large empty arenas, worker exit, exposition and existing compaction with partial input/queued output/deadlines. All 97 library tests pass in 0.50 seconds; Clippy with tests and warnings denied and rustfmt checks pass. The clean snapshot excludes the three protected pre-existing overlays. Only src/server.rs, src/server/arena_tests.rs and src/metrics.rs differ from the committed base, and the selected build confirms fresh:false recompilation.

Two separate ordinary one-second churn screens, control then selected, verify 131,576 and 131,672 complete lifecycles respectively. This is a smoke comparison, not a repeated speedup estimate. The selected ordinary full-population case passes all 32/32 windows, all 800,000 private and 1,048,576 fanout observations, exact counters, unchanged FD baseline and final resource checks, with zero routing-copy bytes. All processes exit normally. Small arenas may remain warm in the churn cases, which is reflected by the gauge rather than called a leak. The new gauge does not change routing, FIFO, output charging, deadlines or arena growth/reclamation policy.

Total configured traffic is eight seconds: four diagnostic plus two churn plus two selected population seconds. Setup, dumps, layout compilation and checked teardown add wall time. No ordinary traffic overlaps builds, tests, profiles, analysis, compression or plots. Existing manual services and convenience binaries were not promoted/restarted, and pre-existing edits remain byte-identical.

Exact invocations, raw profile dumps/headers, symbolized allocation groups, layout probe patch/logs, selected code patch/source, builds, client receipts and selected full per-user CSVs are archived. Diagnostic latency CSVs stay in local artifacts and are not presented as performance results. Frozen executables remain at original paths and are pinned by SHA; the binary is needed to regenerate symbols, but not to audit the recorded totals. Run `python3 verify.py` here for the portable offline audit. To rerun the diagnostic, copy current-population-heap.py and analyze-current-population-heap.py to the repository artifacts directory and use the saved commands with fresh heap/output prefixes; they resolve existing scripts from that location. The diagnostic driver is archived evidence, not a new production runner option.
