# Capture queued JavaScript command values

Selected: command input is captured at invocation, rather than retaining mutable caller data until the wire queue advances. Previously even an idle setVariable() waited until a microtask to encode its value. Mutation before that turn changed the stored data; transferring a queued value buffer made the send fail. The existing FIFO wire queue, single pending response, request timeouts, protocol validation and Close rules remain. No request ID, dependency, public mode or relay runtime change is added.

Four original failures are reproduced with the native/bridge fixture: nested object/byte mutation before the first turn, buffer transfer behind a pending command, mutation in a reentrant queued write, and actual native variable contents. The original full run has four failures. Corrected mock transport tests copy bytes into ordinary Uint8Array storage before decoding, matching real ArrayBuffer receive behavior rather than comparing Node Buffer prototypes. The native variable regression is independent of that mock.

Ordinary requests now prepare their existing CBOR envelope once at invocation, then send that exact encoded frame only when their FIFO turn begins. Local encoding failures are retained and rejected at their queue position without a wire packet; the next command can continue. Already closed clients reject before evaluating values. Request timeout validation and timer start remain at the queue turn, so local preparation and queue waiting do not consume the existing acknowledgement timeout.

A straight eager-encoding prototype corrupted the outer packet when a getter enqueued another command. cbor-x uses shared output state and cannot safely encode that nested packet recursively. That unselected prototype and its corrected failing test log are retained. The selected implementation counts active encoder calls across Relay instances. A reentrant request reserves its FIFO position, captures cloneable input with structuredClone and defers encoding until its turn. It therefore cannot overwrite the outer packet. Ordinary requests do not take that extra clone. SharedArrayBuffer storage retains standard structured-clone sharing semantics and must stay synchronized/stable until the request settles; this change is not an atomic snapshot of concurrently modified shared memory.

Tests cover getter evaluation exactly once, outer/inner FIFO, a mutable nested write, a request made from an ordinary application-send getter, encoding-failure identity and position, recovery, and already-closed fast failure. Existing malformed-response, timeout, client Close and native/legacy compatibility tests remain enabled. The final 52-test suite passes in 1.117 seconds. Final connections, sessions, queued bytes, variables, read-buffer reservations and output queue capacity are zero; both disposable native/bridge processes exit zero.

Because the encoder guard also wraps application serialization, a separate short SDK-local screen checks ordinary 1 KiB sends. Each process warms 20,000 calls, then times three rounds of 100,000 sends into a counting sink. The final source runs before/after/after/before on CPU 8. Source hashes, Node version, commands, all round timings and encoded-byte counts are retained. Process median nanoseconds/send are 356.38 and 369.55 before, 376.59 and 358.28 after. Ranges overlap; this is not a speedup claim or a transport benchmark. Each process emits the same 331,840,000 counted encoded bytes including warmup. Earlier Boolean-guard screens had slower candidate repeats and remain archived separately as unselected implementation observations; do not pool them with the final source. The counter makes nested depth explicit, and no general performance superiority is inferred from these small samples.

The existing browser build is regenerated. A separate test imports that artifact with Buffer absent during module loading, selecting the codec's browser Uint8Array path, then uses Node's real WebSocket against native. A variable write queued behind a read retains its original object fields and bytes after mutation and buffer transfer. This passes in about 62 ms. It is not an actual browser UI/rendering test. No native or C++ benchmark campaign is run for this JavaScript ownership correction, and no 100,000-user capacity/latency result is inferred.
